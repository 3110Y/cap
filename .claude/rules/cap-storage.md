# Rule: cap-storage

## Файл репозиториев

**Путь:** `~/.config/cap/repositories.yml`

**Формат:**

```yaml
- id: a1b2c3d4
  url: https://github.com/user/claude-skills
- id: e5f6g7h8
  url: https://gitlab.com/team/agents
```

`id` генерируется автоматически при добавлении репозитория (первые 8 символов SHA-1 от URL + временной метки).

## Структура удалённого репозитория

Репозиторий должен следовать жёсткой иерархии и обязательно содержать в корне файл `index.json`.

```
<repository-root>/
├── index.json                     # ОБЯЗАТЕЛЬНЫЙ индексный файл
├── skills/
│   └── <vendor>/
│       └── <skill-name>/
│           └── <version>/
│               ├── <skill-name>.md
│               ├── README.md
│               └── ...
├── agents/
│   └── <vendor>/
│       └── <agent-name>/
│           └── <version>/
│               ├── <agent-name>.md
│               └── ...
├── commands/
├── hooks/
└── rules/
```

**Пример полного пути к версии примитива:**
`/skills/anthropic/code-review/1.2.0/code-review.md`

## Структура кеша CAP

**Корень кеша:** `~/.cache/cap/`

```
~/.cache/cap/
├── indexes.json                   # объединённый индекс всех репозиториев
└── repos/                         # клоны репозиториев
    ├── <repo-id-1>/
    │   └── (содержимое репозитория)
    ├── <repo-id-2>/
    └── ...
```

- `indexes.json` — создаётся и обновляется командой `cap update`. Содержит объединённые данные из всех `index.json` всех активных репозиториев.
- `repos/<repo-id>/` — полная копия удалённого репозитория.

## Проектная директория и пространства имён

Установленные примитивы размещаются в:

```
.claude/<type>/<vendor>/<name>/<version>/
```

После установки примитив становится доступным Claude через пространство имён:

```
cap:<vendor>:<name>
```

Например, `cap:anthropic:code-review`. Внутри `.claude` могут находиться несколько версий одного примитива, но активной считается последняя установленная (или явно выбранная пользователем).
