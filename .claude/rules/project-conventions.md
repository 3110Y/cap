# Rule: project-conventions

## Источник правды

Спецификация проекта — источник правды для нетривиальных решений:

- `CLAUDE.md` — высокоуровневый обзор, глоссарий, стек, слоистая архитектура.
- `.claude/rules/cap-storage.md` — пути хранения и структура кеша.
- `.claude/rules/cap-index-format.md` — форматы `index.json`, `indexes.json`, frontmatter.
- `.claude/rules/cap-cli-commands.md` — справочник CLI.
- `.claude/rules/cap-technical-notes.md` — технические заметки.

Перед архитектурными или API-решениями — читать эти документы; не вводить предположений «по умолчанию», если спек их не оговаривает.

## Фиксированный стек

Стек зафиксирован пользователем на старте проекта и не подлежит обсуждению без явного запроса:

- **Язык:** Go 1.21+.
- **CLI:** Cobra. Не предлагать `urfave/cli`, `kingpin`, `flag` и т.п. как альтернативу.
- **DI:** Google Wire. Не предлагать `uber/fx`, `dig`, ручную сборку зависимостей как альтернативу.
- **Git:** `go-git` или внешний `git`.
- **Целевые платформы сборки:** macOS, Windows, Ubuntu — кросс-компиляция через `make build-all`.

Если пользователь явно спрашивает альтернативы — обсудить, но по умолчанию придерживаться зафиксированного стека.

## Слоистая архитектура — обязательна

Новые сущности и команды CLI добавляются **полным набором слоёв**:

1. `internal/domain/entity/<name>.go`
2. `internal/domain/repository/<name>_repository.go` (интерфейс)
3. `internal/integration/repository/<name>_repository.go` (реализация)
4. `internal/application/service/<name>_service.go`
5. `internal/presentation/handler/<name>_handler.go`
6. `internal/presentation/command/<name>.go` + регистрация в `root.go`
7. Обновление `internal/integration/di/wire.go` и перегенерация `wire_gen.go`.

Для этого используется команда `/add-entity` (см. `.claude/commands/add-entity.md`).

Не сокращать слои (например, «маленький сервис без репозитория» или «команда напрямую вызывает Git-клиент») — это нарушает инверсию зависимостей и ломает тестируемость.

## Работа с `index.json`

- `index.json` в удалённом репозитории примитивов — **обязателен**.
- CAP **только читает** этот файл; не генерирует и не модифицирует его.
- Владелец репозитория сам поддерживает `index.json` в актуальном состоянии.
- Репозиторий без `index.json` — невалидный; при синхронизации пропускается с предупреждением.
